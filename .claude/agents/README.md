# agents

เอเจนต์เฉพาะทางของโปรเจกต์หารเมา แบ่งตาม **ขอบเขตไฟล์** เพื่อให้สั่งงานขนานกันได้โดยไม่แก้ทับกัน

## ทีม

| agent | ขอบเขตไฟล์ (แก้ได้) | หน้าที่ | delegate ต่อได้ |
|---|---|---|:---:|
| [hanmao-lead](hanmao-lead.md) | ไม่แก้โค้ดฟีเจอร์ | **หัวหน้าทีม** — แตกงาน กระจายให้ลูกทีม รวมผล | ✅ |
| [hanmao-domain](hanmao-domain.md) | `src/domain/**`, `src/utils/**` | สูตรหาร, settle-up, โมเดลข้อมูล, ยูทิลิตี้ pure (`geo.ts`, `id.ts`) | ✗ |
| [hanmao-frontend](hanmao-frontend.md) | `app/**`, `src/ui/**` | หน้าจอ, ธีม, a11y, empty state | ✗ |
| [hanmao-data](hanmao-data.md) | `src/data/**`, `infra/supabase/**` | store API, persist, dual-mode, realtime, SQL | ✗ |
| [hanmao-test](hanmao-test.md) | `tests/**`, `playwright.config.ts` | Playwright E2E | ✗ |
| [hanmao-docs](hanmao-docs.md) | ไฟล์ `.md` | เอกสารให้ตรงโค้ด + ADR | ✗ |
| [hanmao-reviewer](hanmao-reviewer.md) | อ่านเท่านั้น | รัน tsc/e2e/build + ตรวจกฎโปรเจกต์ | ✗ |

มีแต่ `hanmao-lead` ที่ถือ Agent tool → **delegate ได้ชั้นเดียว** (คุณ → lead → ลูกทีม) ลูกทีมแตกลูกต่อไม่ได้ กันงานบานปลายและกัน agent วนเรียกกันเอง

## วิธีสั่ง

```
# งานหลายเลเยอร์ — ให้หัวหน้าทีมกระจาย
"ใช้ hanmao-lead: เพิ่มฟีเจอร์แยกบิลตามรอบ (เช้า/เย็น)"

# งานเลเยอร์เดียว — สั่งตรงตัวที่ตรงขอบเขต เร็วกว่า
"ใช้ hanmao-test: เขียนเทสหน้าสมาชิกกรณีลบคนที่เป็นคนจ่าย"
```

## วงจรการทำงาน (บังคับทุกรอบ)

```
  ผู้ใช้สั่ง
      ↓
  hanmao-lead        แตกงานตามขอบเขตไฟล์ (ไม่เขียนโค้ดฟีเจอร์เอง)
      ↓  สั่งขนานกันได้ ถ้าไม่แตะไฟล์เดียวกัน
  domain · data · frontend · test · docs   ←  reviewer ตรวจปิดท้าย
      ↓  ลูกทีมรายงานกลับ (ทุกตัว รวมตัวที่ "ไม่มีงาน")
  hanmao-lead        รวมผล + ให้ reviewer ยืนยันตัวเลข
      ↓
  รายงานผู้ใช้ → ⏸ หยุดรอคำสั่งรอบต่อไป
```

**สองกฎที่แรงที่สุดของทีมนี้:**

1. **ทำทีละรอบ** — จบรอบแล้วรายงานแล้วหยุด **ห้ามต่อรอบถัดไปเอง** ถึงจะเห็นงานต่อชัดแค่ไหน
2. **⛔ เทสเจอเคสแดง = หยุด รายงานผู้ใช้ก่อน ห้ามใครแก้เอง** — ทั้งห้ามแก้โค้ดตามเทส
   และห้ามแก้เทสให้ผ่าน เพราะเคสแดงอาจเป็น *เทสคาดผิด* ไม่ใช่โค้ดผิด
   ต้องรายงาน: **แดงกี่เคส / ทั้งหมดกี่เคส**, ค่าที่คาด vs ที่ได้จริง, ไฟล์:บรรทัดที่สงสัย, ใครควรแก้

## รายงานกลับหัวหน้าทีม

ลูกทีมทุกตัวรายงานรูปแบบนี้ (lead เอาไปประกอบเป็นตารางให้ผู้ใช้):

```
ทำอะไร: <สรุป 1-2 บรรทัด>
ไฟล์ที่แก้: <path:บรรทัด> (ถ้าไม่แก้อะไรให้เขียน "ไม่แก้ไฟล์")
ผลรันที่รันเอง: tsc <ผ่าน/แดง> · unit <ผ่าน>/<ทั้งหมด> (แดง N, todo M) · e2e <ผ่าน>/<ทั้งหมด>
ติดอะไร: <ที่ทำไม่ได้/ต้องรอคนอื่น/ต้องผู้ใช้ตัดสิน — ถ้าไม่ติดเขียน "ไม่ติด">
ใครต้องแก้ตาม: <agent + สิ่งที่ต้องแก้ — ถ้าไม่มีเขียน "ไม่มี">
เคสแดงที่ยังไม่แก้: <ชื่อเทส + คาด X ได้ Y + สมมติฐานว่าใครผิด>
```

- **ตัวเลขเทสต้องรันเองแล้วอ่านผลเอง** ห้ามลอกจาก agent อื่นหรือจากบรีฟที่ได้รับมา
- **ห้ามรายงานว่าเสร็จถ้ายังไม่เสร็จ** — ทำได้ครึ่งเดียวให้บอกว่าครึ่งไหนไม่ได้ทำและเพราะอะไร
- **ถ้าบรีฟที่ได้รับมาขัดกับโค้ดจริง ให้เชื่อโค้ดแล้วแก้บรีฟกลับในรายงาน**

## ตัวอย่างหนึ่งรอบเต็ม

**ผู้ใช้:** "ใช้ hanmao-lead: เพิ่มช่อง 'ทิป' ต่อบิล แล้วหารตามสัดส่วนเหมือน service charge"

**lead** อ่าน `types.ts` / `split.ts` / `store.tsx` ก่อน แล้วแตกเป็น 5 ชิ้น ตกลง signature ให้นิ่งก่อนสั่ง
(`Bill.tipPct?: number` — optional เพราะ state เดิมในเครื่องผู้ใช้ไม่มีฟิลด์นี้) แล้วสั่ง:

| ลำดับ | agent | งาน |
|---|---|---|
| 1 (ขนาน) | `hanmao-domain` | เพิ่ม `tipPct?` ใน `Bill` + รวมทิปเข้า `factor` ของ `computeBill` |
| 1 (ขนาน) | `hanmao-data` | map `tip_pct` ↔ `tipPct` + `patch-006-tip.sql` (idempotent) |
| 2 | `hanmao-frontend` | ช่องกรอกทิปในหน้าบิล (a11y + `baht()` + `colors`) |
| 3 | `hanmao-test` | unit สูตรทิป + E2E กรอกทิปแล้วยอดเปลี่ยน |
| 4 | `hanmao-reviewer` | รัน tsc/unit/e2e/export + ตรวจกฎ |
| 5 | `hanmao-docs` | SPEC + README + ขั้นตอนรัน SQL |

**สิ่งที่ lead รายงานกลับผู้ใช้:**

## ลำดับการพึ่งพา (lead ใช้จัดคิว)

```
domain ──┐
         ├─→ frontend ─→ test ─→ reviewer ─→ docs
data   ──┘
```
`domain` + `data` รันขนานกันได้ถ้าไม่แตะไฟล์เดียวกัน · `frontend` รอ API/สูตรนิ่งก่อน · `docs` ปิดท้าย

## เพิ่ม agent ใหม่

สร้าง `<name>.md` + frontmatter (`name`, `description`, `tools`) แล้ว **แบ่งตามขอบเขตไฟล์ที่ไม่ทับกับตัวอื่น** —
ในเนื้อไฟล์ต้องระบุ: ไฟล์ที่แก้ได้/ห้ามแตะ, กฎที่ห้ามละเมิด, และสิ่งที่ต้องทำก่อนปิดงาน
(verify + ลิงก์มาที่ [รายงานกลับหัวหน้าทีม](#รายงานกลับหัวหน้าทีม) + กฎ ⛔ เทสแดงห้ามแก้เอง)
แล้วเพิ่มแถวในตาราง **ทั้งไฟล์นี้และ [CLAUDE.md](../../CLAUDE.md)** ไม่งั้น lead จะไม่รู้ว่ามีตัวใหม่
