# ADR 0003 — `transferKey` ผูกกับยอดเงิน (เลิกใช้ `allSettled`)

- สถานะ: Accepted — **ยังใช้อยู่กับ state ที่ยอดนิ่ง**;
  ส่วน "key ผูกยอด + ผูกทิศทาง" ถูก **supersede เฉพาะกรณียอดลอยตามเวลา** โดย
  [ADR 0006](0006-stable-settle-topology.md) และข้อยกเว้นการ prune ถูก **ยกเลิก** (ดูท้ายไฟล์)
- วันที่: 2026-07-31

## บริบท
`state.settlements` เก็บ key ของรายการโอนที่ผู้ใช้ติ๊กว่า "โอนแล้ว"
เดิม key คือ `` `${fromId}>${toId}` `` — ผูกแค่ "ใครโอนให้ใคร" ไม่ผูกจำนวนเงิน

ปัญหา: หลังติ๊กว่าโอนแล้ว ถ้ามีคนเพิ่มบิลใหม่ / แก้ราคา / เพิ่มสมาชิก แล้วยอดที่ A ต้องโอนให้ B
เปลี่ยนจาก 300 เป็น 800 บาท key เดิมยังตรงอยู่ → แอปยังโชว์ว่ารายการนั้น "โอนแล้ว"
ทั้งที่ยังค้างอีก 500 และ `allSettled()` ก็ยังปลดล็อกปุ่ม "เคลียร์ทั้งหมด/ปิดกลุ่ม" ให้ลบข้อมูลได้
= แอป **โกหกว่าเงินถูกโอนไปแล้ว** ซึ่งเป็นความผิดพลาดที่ยอมรับไม่ได้ในแอปเรื่องเงิน

อีกจุด: `allSettled()` คืน `false` เมื่อไม่มีรายการโอนเลย ทำให้กลุ่มที่หารลงตัวพอดี
(ทุกคนออกเงินเท่าส่วนตัวเอง) ไม่มีทางปิดกลุ่มได้เลย

## ตัวเลือกที่พิจารณา
1. **ใส่ยอดเงินไว้ใน key** (`from>to@amount`) ให้ยอดเปลี่ยน = ติ๊กเดิมเป็นโมฆะเอง ← เลือก
2. เก็บ settlements เป็น object `{ from, to, amount, at }` — ยืดหยุ่นกว่า แต่ต้อง migrate
   คอลัมน์ `groups.settlements` + RPC + state ที่ persist ไว้แล้ว และตรรกะเทียบก็เท่ากับข้อ 1
3. คง key เดิม แล้วล้าง settlements ทั้งก้อนทุกครั้งที่ยอดเปลี่ยน — เสียการติ๊กที่ยังถูกต้องอยู่ไปด้วย
   (คนอื่นในกลุ่มที่โอนจริงแล้วต้องมาติ๊กใหม่หมดทั้งที่ยอดของเขาไม่ขยับ)

## การตัดสินใจ
- `transferKey(t)` = `` `${fromId}>${toId}@${round2(t.amount).toFixed(2)}` `` เช่น `B>A@550.00`
- แทน `allSettled()` ด้วย **`nothingOwed(transfers, settlements)`** ที่คืน `true` เมื่อ
  ไม่มีรายการโอนเลย **หรือ** ทุกรายการถูกติ๊กแล้ว (หน้าสรุปกันเคส "ยังไม่มีข้อมูล" ด้วยเงื่อนไข `hasSummary` แยก)
- เพิ่ม `pruneSettlements()` และให้ store เรียกให้เองทุกครั้งที่ mutate ข้อมูลที่กระทบยอด
  (+ ตอนโหลด state จากเครื่อง) เพื่อไม่ให้ key ที่หมดอายุค้างสะสม
- ยกเว้นการ prune เมื่อมีบิลโหมด `time` และยังมีคนไม่กลับ — ยอดขยับตามเวลาเรื่อย ๆ
  ถ้า prune จะไปลบ key ที่หน้าจอกำลังใช้อยู่
  > **ข้อนี้ถูกยกเลิกแล้ว** (ดูภาคผนวกท้ายไฟล์) — ปัจจุบัน `pruneState()` prune ทุกเคส

## ผลที่ตามมา
- **ผลข้างเคียงที่ตั้งใจ (ผู้ใช้จริงจะเจอ)**: settlements รูปแบบเก่าที่ค้างอยู่ในเครื่องผู้ใช้
  (`hanmao:state:v1`) และในคอลัมน์ `groups.settlements` ของกลุ่มที่เปิดอยู่ **จะไม่ match key ใหม่**
  → รายการเหล่านั้นกลับไปแสดงเป็น "ยังไม่โอน" ต้องติ๊กใหม่
  ยอมรับผลนี้อย่างจงใจ: ทางเลือกที่ปลอดภัยกว่าคือให้ผู้ใช้ติ๊กซ้ำ (เสียเวลา)
  ไม่ใช่ให้แอปอ้างว่าเงินถูกโอนไปแล้วโดยไม่จริง (เสียเงิน)
  ไม่มี migration ให้ — key เก่าไม่มีข้อมูลยอดจึงเดาไม่ได้ว่าตรงกับยอดปัจจุบันหรือไม่
- ไม่ throw เมื่อพบ key รูปแบบเก่า แค่ไม่ match (fail-safe ไปทาง "ยังไม่โอน")
- โค้ดที่แสดง/ติ๊กรายการโอนต้องใช้ `transferKey()` เสมอ **ห้ามประกอบ key เอง** ในหน้าจอ
- เอกสาร/เทสที่ยังอ้าง `allSettled` หรือ key `from>to` ถือว่าล้าสมัย

## ภาคผนวก (เพิ่มภายหลัง) — ปัจจุบัน `transferKey` มี 2 รูปแบบ

การตัดสินใจในไฟล์นี้ยังเป็นค่าตั้งต้นและยังใช้อยู่กับ **state ที่ยอดนิ่ง** แต่มีข้อจำกัดที่พบภายหลัง:
บิลโหมด `time` ที่ยังมีคนไม่กลับทำให้ยอด **ลอยไปตามนาฬิกาเอง** — key ที่ผูกยอด (และผูกทิศทาง)
จึงเป็นโมฆะเองทั้งที่ผู้ใช้ไม่ได้แก้ข้อมูลอะไร ⇒ ปุ่มปิดกลุ่ม/กล่อง "จ่ายครบทุกคนแล้ว" หายเอง

สิ่งที่เปลี่ยนไปจากไฟล์นี้ (รายละเอียดเต็มอยู่ที่ [ADR 0006](0006-stable-settle-topology.md)):

| หัวข้อ | ADR 0003 (เดิม) | ปัจจุบัน |
|---|---|---|
| รูปแบบ key | `` `${from}>${to}@ยอด` `` แบบเดียว | 2 แบบ — ยอดนิ่งใช้แบบเดิม; **ยอดลอยใช้** `` `${idน้อย}|${idมาก}@${stamp}` `` |
| key ผูกอะไร | ทิศทาง + ยอดเงิน | ยอดนิ่ง: เหมือนเดิม · ยอดลอย: **คู่คน + ลายนิ้วมือข้อมูล** (ไม่ผูกยอด ไม่ผูกทิศ) |
| ข้อยกเว้นการ prune ตอนโหมด `time` | ข้าม prune | **ไม่ต้องยกเว้นแล้ว** — key ยอดลอยนิ่งข้าม `asOf` ที่ต่างกัน จึง prune ได้ทุกเคส |

เจตนาเดิมของ ADR นี้ยังไม่เปลี่ยน — **แอปห้ามอ้างว่าเงินถูกโอนแล้วโดยไม่จริง**:
ตอนคนสุดท้ายติ๊ก "กลับแล้ว" ยอดหยุดลอย key ย้ายกลับมาเป็นแบบผูกยอด ⇒ ติ๊กชุดที่ทำไว้ระหว่างยอดลอย
เป็นโมฆะทั้งชุด **ต้องติ๊กใหม่บนยอดปิดจริงก่อนปิดกลุ่ม** (ตาข่ายกันเงินหายชั้นสุดท้าย)

อีกจุดที่ทำให้ key เป็นโมฆะเองได้แม้ยอดนิ่ง: การเกลี่ยเศษ 1 สตางค์เคย **ขึ้นกับลำดับแถวใน array**
แก้แล้ว ดูภาคผนวกของ [ADR 0002](0002-integer-cents-largest-remainder.md)
