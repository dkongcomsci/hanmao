# ADR 0004 — ไม่ใส่เบอร์พร้อมเพย์ในรูปสรุปที่แชร์

- สถานะ: Accepted
- วันที่: 2026-07-31

## บริบท
หน้าสรุปมีการ์ด (`shareCard`) ที่จับภาพเป็น PNG ด้วย `shareViewAsImage()` แล้วส่งต่อ
(web = ดาวน์โหลดไฟล์, native = share sheet) ไว้โพสต์ในกลุ่มแชทของวง

เดิมการ์ดนี้พิมพ์เบอร์พร้อมเพย์ของผู้รับเงินลงในรูปด้วย เพื่อความสะดวก
แต่พร้อมเพย์คือ **เบอร์มือถือหรือเลขบัตรประชาชน** = ข้อมูลส่วนบุคคล
รูปที่แชร์ออกไปควบคุมปลายทางไม่ได้เลย (ถูก forward ต่อ, ค้างใน cloud backup ของแชท,
คนที่ไม่ได้อยู่ในวงเห็นได้) และเจ้าของเบอร์ไม่ได้เป็นคนกดแชร์เองด้วยซ้ำ —
คนที่กดแชร์คือใครก็ได้ในวงที่เปิดหน้าสรุป

## ตัวเลือกที่พิจารณา
1. **ตัดพร้อมเพย์ออกจากการ์ดที่แชร์ทั้งหมด** เก็บไว้เฉพาะบนหน้าจอ ← เลือก
2. ใส่แบบปิดบางส่วน (เช่น `08x-xxx-1234`) — ยังรั่วบางส่วน และปิดแล้วก็โอนไม่ได้ ไม่ได้ประโยชน์อะไร
3. มี toggle ให้ผู้ใช้เลือกว่าจะใส่ไหม — คนกดแชร์ไม่ใช่เจ้าของเบอร์ จึงไม่ใช่คนที่ควรตัดสินใจแทน
   และค่าเริ่มต้นจะกลายเป็นสิ่งที่คนส่วนใหญ่ใช้อยู่ดี

## การตัดสินใจ
- `shareCard` มีแค่: แบรนด์ + ชื่อวง, ยอดรวมทุกบิล, ยอดที่แต่ละคนต้องจ่าย, ใครโอนให้ใคร (ชื่อ + ยอด)
- เบอร์พร้อมเพย์แสดงเฉพาะ **บนหน้าจอ นอกขอบเขตการ์ด** ผ่านปุ่ม "📋 พร้อมเพย์ …" ที่คัดลอกไป clipboard
  (มีทั้งหน้าสรุปและแท็บ "ฉัน")
- มีคอมเมนต์กำกับในโค้ดตรงจุดที่แก้ง่ายที่สุด และมีข้อความบนจอบอกผู้ใช้ว่า
  "รูปสรุปไม่มีเบอร์พร้อมเพย์ ส่งต่อในกลุ่มได้ปลอดภัย" เพื่อไม่ให้มีคนเข้าใจว่าฟีเจอร์หาย

## ผลที่ตามมา
- คนรับรูปต้องไปเปิดแอป/ขอเบอร์เองเพื่อโอน — ยอมแลกความสะดวกกับความปลอดภัยของข้อมูลคนอื่น
- ใครจะเพิ่มฟิลด์ใหม่เข้า `shareCard` ต้องเช็กก่อนว่าไม่ใช่ข้อมูลส่วนบุคคล
  (ข้อจำกัดนี้อยู่ในกฎของ frontend ด้วย)
- ฟีเจอร์ในอนาคต "QR PromptPay จากยอดจริง" ต้องออกแบบให้ **ไม่ไปอยู่ในรูปที่แชร์** ด้วยเหตุผลเดียวกัน
